# RustOS Requirements

A preemptive, priority-based real-time operating system (RTOS) written in Rust for RISC-V embedded systems.

---

### 2.7 Kernel API and Behavioral Semantics

The kernel requirements above are not implementable without explicit behavioral rules. This section defines API-level semantics and ISR restrictions.

#### 2.7.1 API Surface

| Requirement ID | Description                                                                                                                | Priority |
|----------------|----------------------------------------------------------------------------------------------------------------------------|----------|
| API-001        | The kernel shall define a public API surface for tasks, time, and synchronization (documented and stable within a release) | Must     |
| API-002        | All fallible kernel APIs shall return `Result<T, Error>` (no panics in normal error cases)                                 | Must     |
| API-003        | Kernel APIs callable from interrupt context shall be explicitly separated (e.g., `*_from_isr`)                             | Must     |
| API-004        | The kernel shall define maximums as compile-time constants (e.g., `MAX_TASKS`, `MAX_PRIORITIES`)                           | Must     |

#### 2.7.2 Scheduling Rules

| Requirement ID | Description                                                                                                                           | Priority |
|----------------|---------------------------------------------------------------------------------------------------------------------------------------|----------|
| API-005        | Priority ordering shall be total and consistent: lower numeric value represents higher priority (0 highest)                           | Must     |
| API-006        | Ready selection shall be deterministic: pick the highest-priority ready task; ties are handled per SCHED-009 if enabled               | Must     |
| API-007        | The idle task shall never block and shall not starve higher priorities                                                                | Must     |
| API-008        | `yield()` shall move the current task to the end of its ready queue (only within same priority)                                       | Should   |
| API-009        | `sleep(ticks)`/`delay_until()` shall wake tasks on or after the requested tick; rounding rules shall be specified (default: round up) | Should   |

#### 2.7.3 Interrupt Context Rules

| Requirement ID | Description                                                                                                                                                                | Priority |
|----------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------|
| ISR-001        | ISRs shall not call blocking APIs (e.g., mutex lock, queue receive)                                                                                                        | Must     |
| ISR-002        | ISRs may only use `*_from_isr` APIs that are guaranteed non-blocking and bounded in time                                                                                   | Must     |
| ISR-003        | ISRs shall not perform dynamic initialization or logging that can deadlock (e.g., acquiring a normal mutex)                                                                | Must     |
| ISR-004        | If an ISR unblocks a higher-priority task, the system shall request a reschedule at ISR exit (deferred context switch allowed)                                             | Must     |
| ISR-005        | Nested interrupts: if the platform does not support interrupt priority/nesting, the kernel shall treat interrupt handling as non-preemptible except for explicit re-enable | Should   |

#### 2.7.4 Error Model

| Requirement ID | Description                                                                                                                                    | Priority |
|----------------|------------------------------------------------------------------------------------------------------------------------------------------------|----------|
| ERR-001        | The kernel shall define a unified `Error` enum including at least: `Timeout`, `WouldBlock`, `InvalidId`, `NotOwner`, `QueueFull`, `QueueEmpty` | Must     |
| ERR-002        | Timeout semantics shall be consistent across primitives (0 ticks means poll/non-blocking; `None` means wait forever if supported)              | Should   |

## 12. Known Limitations

| Limitation ID | Description                                                                                                                                               |
|---------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------|
| LIM-001       | No priority inversion handling in mutex (no priority inheritance)                                                                                         |
| LIM-002       | No strict FIFO fairness in semaphore (priority-based wake)                                                                                                |
| LIM-003       | Single interrupt priority level (no hardware nesting)                                                                                                     |
| LIM-004       | No dynamic task creation after boot (static only)                                                                                                         |
| LIM-005       | Fixed memory layout (128 KB total BRAM)                                                                                                                   |
| LIM-006       | Machine mode used for RTOS (supervisor mode with SV32 available but unused)                                                                               |
| LIM-007       | Tick counter wraps after ~49 days at 1 ms rate                                                                                                            |
| LIM-008       | No instruction/data caches (direct BRAM access via LMB)                                                                                                   |
| LIM-009       | No MMU/MPU protection (flat memory model)                                                                                                                 |
| LIM-010       | DDR3 and external Flash not used by default (BRAM only)                                                                                                   |
